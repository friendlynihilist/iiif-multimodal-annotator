# Data model

Every annotation is an `oa:Annotation` (W3C Web Annotation). The default
profile (INTERIM, bundled under `profiles/interim-geko/`) layers four
ontologies on top:

| Ontology | What it adds |
|----------|-------------|
| **LRMoo** | `F1_Work` and `F2_Expression` as target/body class hooks |
| **GEKO** | `hasEkphrasticModality` predicate and the three modality concepts (denotation, dynamisation, integration) |
| **MLAO** | `hasAnchor` blank node with `isAnchoredTo` (real-world entity) and `hasConceptualLevel` (interpretive tier) |
| **HICO + PROV-O** | `InterpretationAct` activity attached via `prov:wasGeneratedBy` |

The tool-owned namespace `mma:` (`https://w3id.org/multimodal-annotator/ns/`,
configurable via `BASE_NS`) carries one predicate: `mma:profile` — the IRI
of the profile under which the annotation was created.

## Linking annotations: dual target

A linking annotation connects a text span to an image region. The body
carries the text; the target is a two-element array:

1. A `lrmoo:F2_Expression` `oa:SpecificResource` pointing at the
   facsimile canvas with a `FragmentSelector` over the line region
   (PAGE-XML xywh).
2. A `lrmoo:F1_Work` `oa:SpecificResource` pointing at the visual work
   canvas with a `FragmentSelector` over the painted region.

This "dual target" is the GEKO v2 structural commitment: an ekphrasis
links the expression of a text (where on the page it physically is) to
the work it iconographically refers to.

When the source text is plain text or TEI (no facsimile coordinates),
the F2 target is omitted and the annotation degrades to a single
F1 target.

## Anchor (MLAO)

After a linking annotation is saved, the UI prompts for an optional
anchor. An anchor binds the annotation to:

- a real-world entity (a Wikidata Q-IRI, or a user-minted custom entity
  under `mma:entities/<ulid>`),
- typed by an entity class (default `crm:E1_Entity`, configurable in
  the Data Model tab),
- optionally at a conceptual level (one of the three ICON / Panofsky
  tiers: pre-iconographical, iconographical, iconological).

The anchor is a blank node `[ a mlao:Anchor ]` attached to the
annotation via `mlao:hasAnchor`. When the entity is custom, its
`rdf:type` and `rdfs:label` triples are stored in the same named graph
as the annotation (auto-cleanup on delete).

Re-anchoring is atomic: a single SPARQL Update `DELETE`s the previous
anchor blank node and its triples, then `INSERT`s the new ones in one
transaction.

## Provenance (HICO + PROV-O)

Every annotation carries an `InterpretationAct` minted at create time
and accumulated on update:

```turtle
<annotation> prov:wasGeneratedBy <annotation/interpretation/<ulid>> .

<annotation/interpretation/<ulid>>
    a hico:InterpretationAct, prov:Activity ;
    dcterms:creator <DEFAULT_CREATOR_IRI> ;
    prov:startedAtTime "..."^^xsd:dateTime ;
    rdfs:comment "auto-generated by the gateway" .
```

`PUT` does not overwrite Acts: it creates a new one and stamps the
previous-latest with `dcterms:isReplacedBy <new>`.

## JSON-LD example

A linking annotation exported by the GEKO export (`Export` button in
the Annotate toolbar), with an anchor to Wikidata Q14798562 ("La
Fornarina") at the iconographical level:

```json
{
  "@context": "https://w3id.org/multimodal-annotator/ns/contexts/multimodal-context.jsonld",
  "id": "https://w3id.org/multimodal-annotator/ns/annotations/demo/01ksr6...",
  "type": "Annotation",
  "motivation": "linking",
  "created": "2026-05-29T12:14:30Z",
  "body": {
    "type": "TextualBody",
    "value": "il turbante di seta",
    "format": "text/plain"
  },
  "target": [
    {
      "type": "SpecificResource",
      "source": "https://dl.ficlit.unibo.it/iiif/2/19266/canvas/p18",
      "selector": {
        "type": "FragmentSelector",
        "conformsTo": "http://www.w3.org/TR/media-frags/",
        "value": "xywh=412,640,1080,48"
      },
      "type": ["SpecificResource", "lrmoo:F2_Expression"]
    },
    {
      "type": "SpecificResource",
      "source": "https://iiif.europeana.eu/.../canvas/p1",
      "selector": {
        "type": "FragmentSelector",
        "conformsTo": "http://www.w3.org/TR/media-frags/",
        "value": "xywh=412,180,260,140"
      },
      "type": ["SpecificResource", "lrmoo:F1_Work"]
    }
  ],
  "hasEkphrasticModality": {
    "id": "https://w3id.org/geko/#denotation",
    "type": "skos:Concept",
    "label": { "en": ["Denotation"] }
  },
  "hasAnchor": {
    "type": "Anchor",
    "isAnchoredTo": "http://www.wikidata.org/entity/Q14798562",
    "hasConceptualLevel": "https://w3id.org/icon/ontology/IconographicalSubject"
  },
  "profile": "https://w3id.org/multimodal-annotator/ns/profiles/interim-geko"
}
```

When the anchor target is a custom entity instead of a Wikidata IRI,
`hasAnchor.isAnchoredTo` becomes an embedded object with the entity's
type and label so the export is self-describing:

```json
"hasAnchor": {
  "type": "Anchor",
  "isAnchoredTo": {
    "id": "https://w3id.org/multimodal-annotator/ns/entities/9f3c1a...",
    "type": "http://www.cidoc-crm.org/cidoc-crm/E1_Entity",
    "label": { "en": ["a custom term"] }
  },
  "hasConceptualLevel": "https://w3id.org/icon/ontology/PreiconographicalSubject"
}
```

## IRI conventions

| Resource              | Pattern                                                 |
|-----------------------|---------------------------------------------------------|
| Annotation            | `<BASE_NS>annotations/<container>/<ulid>`               |
| InterpretationAct     | `<annotation>/interpretation/<ulid>`                    |
| Custom entity         | `<BASE_NS>entities/<32-char slug>`                      |
| Profile               | `<BASE_NS>profiles/<profile-id>`                        |
| Profile ontology graph| `<BASE_NS>graphs/ontology/<profile-id>`                 |

ULIDs are Crockford Base32, lowercased, generated server-side (annotation
+ act) or client-side via `crypto.randomUUID()` then stripped of dashes
(custom entity).

## Round-trip rules

The system enforces three invariants:

1. An annotation POSTed as JSON-LD, GETed later, expands to the same
   RDF triples. Verified by `pyld.jsonld.expand` equivalence in
   `backend/scripts/test_context_roundtrip.py`.
2. The `@context` URL in any exported annotation resolves to a stable,
   versioned JSON-LD context served from the backend at
   `/contexts/<name>.jsonld`. No floating definitions.
3. An annotation created under profile A and viewed under profile B
   stays identifiable as "from profile A" via its `mma:profile` triple.
